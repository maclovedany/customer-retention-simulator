# 구독 유지·해지 방어 전략 시뮬레이터 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 전략 레버를 움직이면 더미데이터 400개사의 유지율·해지율·매출 변화가 지표 카드 5개와 차트 5개에 즉시 반영되는 발표 시연용 정적 웹 페이지를 만들어 Vercel에 배포한다.

**Architecture:** 파이썬 스크립트가 원자료 엑셀을 정제해 `data.js`(기업 레코드, 월별 집계, 참고값)를 만든다. 브라우저에서는 순수 함수 모듈 `sim.js`가 레버 값으로 결과를 계산하고, `app.js`가 조작부와 지표 카드를, `charts.js`가 ECharts 차트를 갱신한다. 빌드 단계가 없는 정적 폴더이며 Vercel 주소와 `file://` 양쪽에서 실행된다.

**Tech Stack:** Python 3 + pandas + openpyxl (`uv run`으로 실행), 바닐라 JS (모듈 번들러 없음, 전역 객체), ECharts 5.5.0 (폴더에 동봉), Node 25 (테스트 실행), Vercel CLI 50.

**Spec:** `./docs/설계안.md` — 실행자는 이 문서와 설계안을 함께 읽는다. 분류 문장 표, 참고값 계산식, 지표 계산식, 프리셋 규칙은 설계안 5.1·5.2에 있으며 여기서 반복하지 않는다.

### Task 2: 시뮬레이션 모듈 `sim.js`

**Files:**
- Create: `sim.js`
- Create: `tools/test_sim.mjs`

**Interfaces:**
- Consumes: `globalThis.SIM_DATA` (Task 1 구조)
- Produces: 전역 `Sim` (`(typeof window !== 'undefined' ? window : globalThis).Sim = {...}`)

```
Sim.LEVERS: [{ key, group: 'A'|'B'|'C'|null, label, min, max, note }]   // min·max는 0~1
  key 순서: 'salary'(A) 'payRecovery'(B) 'pause'(B) 'annual'(B)
            'consultRate'(C) 'saveRate'(C) 'onboarding'(C) 'alert'(C) 'rechurn'(null)
  범위는 설계안 5.2 표. consultRate의 min은 Sim.levers(refs)에서 refs.consultRate로 대체
Sim.levers(refs) -> LEVERS 사본 (consultRate.min = refs.consultRate ?? 0)
Sim.presets(refs) -> { current, conservative, base, aggressive }   // 각각 { [key]: number }
Sim.run(data, values) -> {
  baseline: Kpi, kpi: Kpi,
  monthly: [{ month, baseRate, simRate, baseActive, simActive }],
  byType:  [{ type, base, sim }],                 // 설계안 5.1 표 순서, 6개 항상 포함
  byGroup: { A: {firms, mrr}, B: {firms, mrr}, C: {firms, mrr} },
  churnMrr: { base, sim },
  firms:   [{ id, status: 'kept'|'churned'|'saved', s, plan, cycle, method, type, mrr }],
  flow:    { requests, consulted, notConsulted, saved, churnedAfterConsult }
}
Kpi = { retention, monthlyChurn, renewalRate, savedMrr, savedRevenue, churnedCount, savedCount }
```

계산 규칙 (설계안 5.2에 더해 여기서 확정하는 것)

- 기업별 레버 확률: `salary` → 유형이 채용 종료형·비용 절감형이면 `values.salary` / `payRecovery` → 결제 실패형 / `pause` → 채용 종료형·결제·계약 불편형 / `annual` → `cycle==='월' && voluntary`이면 `values.annual × (refs.annualFactor ?? 0)` / 상담 → `voluntary && !consulted`이면 `(values.consultRate − c) ÷ (1 − c) × values.saveRate`, `c = refs.consultRate ?? 0`, `c ≥ 1`이면 0 / `onboarding` → 지원 불만형 / `alert` → `voluntary && dropAlert`.
- `s = 1 − Π(1 − p)`, `s' = s × (1 − values.rechurn)`. 레버 몫 = `s' × p_L ÷ Σp` (Σp가 0이면 0).
- 매출 몫은 `pause`만 0.5배. `savedMrr = Σ 몫 × mrr`, `savedRevenue = Σ 몫 × mrr × 남은 개월 수`(해지 월 다음 달부터 마지막 달까지).
- `churnMrr.sim = churnMrr.base − savedMrr`.
- `firms[].status`: `savedCount = round(Σ s')`. 해지 기업을 `s'` 내림차순(같으면 id 오름차순)으로 정렬해 앞의 `savedCount`개가 `'saved'`.
- `flow`: `requests = data.requests.voluntary`, `consulted = requests × values.consultRate`, `saved = consulted × values.saveRate`, 나머지는 뺄셈.
- 분모가 0인 비율은 0으로 둔다.

### Task 4: 차트 5개 `charts.js`

**Files:**

**Interfaces:**

- [ ] **Step 7: 슬라이더 조작 확인** — 실제 크롬에서 열어 슬라이더를 끌며 모든 차트가 끊김 없이 따라오는지 본다. 브라우저 자동화 도구로 조작할 수 없으면 사용자에게 확인을 요청하고, 직접 확인하지 못했다고 보고한다.
