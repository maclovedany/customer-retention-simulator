# 구독 유지·해지 방어 전략 시뮬레이터 설계안

작성일 2026-11-15 · 1조 프로젝트 「B2B 기업 회원 구독 해지 방어 / HR 플랫폼 구독 유지 전략」

## 1. 목적

프로젝트 산출물 '구독 유지 및 해지 방어 전략 실행안'을 최종 발표에서 시연하기 위한 웹 페이지다.
발표자가 전략 레버 값을 바꾸면, 더미데이터 400개사에 그 전략을 적용했을 때의 유지율·해지율·매출 변화가 여러 차트에 즉시 반영된다.
청중이 "어떤 전략이 어느 고객군에서 얼마만큼 효과를 내는가"를 한 화면에서 보게 하는 것이 목표다.

## 2. 목표 · 비목표 · 피해야 할 것

**목표**

- 레버를 움직일 때마다 모든 차트와 지표가 애니메이션과 함께 즉시 갱신된다.
- Vercel에 배포한 주소로 접속해 실행된다. 인터넷이 안 될 때는 같은 폴더의 `index.html`을 더블클릭해도 실행된다.
- 화면의 모든 기준 수치는 `HR플랫폼_B2B구독_더미데이터.xlsx`에서 계산한 값이며 분석 보고서 수치와 일치한다.
- 원자료 엑셀을 고친 뒤 변환 스크립트를 다시 실행하고 재배포하면 화면 전체가 새 데이터를 따른다.
- 레버 구성이 보고서 10쪽의 개선 방안 ①~④와 대응한다 (5.2의 묶음 A·B·C).

**비목표**

- 서버, 로그인, 데이터 업로드, 결과 저장 기능
- 모바일 화면 최적화 (기준 화면은 1920×1080 프로젝터, 최소 1366×768)
- 전략 실행 비용·ROI 계산 (원자료에 비용 정보가 없음)
- 통계적 예측 모델

**피해야 할 것**

- 결과가 "예측"처럼 보이는 것. 효과 크기는 데이터에 없으므로 발표자가 넣는 가정이며, 화면에 "가정 기반 시나리오"임을 항상 표시한다.
- 레버 효과를 단순 합산해 방어 기업 수가 실제 해지 기업 수를 넘는 것.
- 발표 중 값 변경에 차트가 끊기거나 늦게 반응하는 것.

## 3. 제약

- 원자료는 교육용 가상 데이터다. 화면 하단에 이를 명시한다.
- 실행 환경은 `file://`로 여는 정적 파일이다. `fetch`로 JSON을 읽을 수 없으므로 데이터는 스크립트 파일로 내장한다.
- 화면 언어는 한국어다.
- 프로젝트 폴더: `./`

### 5.1 데이터 준비 (`tools/build_data.py`)

원자료 5개 시트를 읽어 분석 보고서와 같은 규칙으로 정제한 뒤 기업 단위 레코드 400건과 월별 집계를 만든다.
`uv run --with pandas --with openpyxl`로 실행한다.

정제 규칙

- 업종 `제조업`→`제조`, `IT/소프트웨어`→`IT·소프트웨어`
- 결제예정일의 `2026.09.04` 형태 문자열을 날짜로 변환
- 월별이용로그 완전 중복 행 제거
- 해지 기업 = 해지요청 시트에서 최종결과가 "해지 확정"인 기업, 기업당 마지막 건 기준
- MRR = 요금제 정가(베이직 30만, 스탠다드 80만, 프리미엄 250만 원) × (연 결제면 0.85)

기업 레코드 필드: 기업ID, 규모, 업종, 요금제, 결제주기, 결제수단, 담당영업, MRR, 구독 시작 월(관측 내), 해지 여부, 해지 월, 해지구분, 해지 유형, 상담 여부, 직전월 이용 급락 여부.

**데이터 연동 (사용자 결정: 방식 B)**

원자료 엑셀의 값을 고치거나 행을 추가한 뒤 스크립트를 다시 실행하면 기준값·참고값·프리셋이 모두 새 데이터에서 다시 계산된다. 시트 이름과 열 이름은 그대로여야 한다.
이 문서에 적힌 수치(137개사, 37% 등)는 모두 "현재 파일 기준" 값이며 코드에 숫자로 박아 넣지 않는다.

- 스크립트는 고정 수치 대신 정합성만 검사하고, 어긋나면 어느 항목인지 알리고 실패한다.
  - 필요한 시트와 열이 모두 있다.
  - 유형별 기업 수의 합이 해지 기업 수와 같다.
  - 해지 기업의 해지 월이 관측 기간 안에 있다.
  - 모든 기업의 MRR이 0보다 크다 (모르는 요금제 이름이 없다).
- 표의 17개 문장에 없는 서술이 들어오면 서술 묶음 없이 선택 사유만으로 분류하고, 그런 건수를 출력한다.
- 스크립트는 실행 끝에 기준값 요약(해지 기업 수, 누적 이탈률, 해지 MRR, 유형별 기업 수, 참고값)을 출력한다.

계산할 수 없는 참고값(분모 0)은 비워 두고 화면에서 "근거 없음"으로 표시한다. 감소율·계수가 음수로 나오면 0으로 둔다.

### 5.2 시뮬레이션 모델 (`sim.js`)

해지한 137개사 각각에 대해 "이 전략들이 있었다면 남았을 확률" `s`를 계산한다.

- 레버 L마다 대상 기업 집합과 기업별 방어 확률 `p_L`이 있다. 대상이 아니면 0이다.
- 여러 레버가 한 기업에 겹치면 `s = 1 − Π(1 − p_L)`로 합친다. 단순 합산하지 않는다.
- 방어 후 재해지율 `r`(기본 23%, 실제 방어 성공 31건 중 7건)을 적용해 `s' = s × (1 − r)`로 쓴다.
- 지표는 기대값으로 계산한다. 해지 기업 수 = Σ(1 − s'), 방어 MRR = Σ s' × MRR.
- 방어된 기업은 관측 종료(2026년 10월)까지 남는 것으로 본다. 누적 방어 매출 = Σ s' × MRR × (해지 월부터 관측 종료까지 개월 수).
- 월별 곡선: 그 달 해지 수는 Σ(1 − s'), 구독 기업 수는 원래 값에 그 전까지 방어된 기대 기업 수를 더한다.
- 레버별 기여 표시는 기업별 `s'`를 각 레버의 `p_L` 비율로 나눠 배분한다.
- 일시정지·요금제 전환 레버의 "매출 50% 반영"은 그 레버에 배분된 몫에만 적용한다. 같은 기업의 다른 레버 몫은 100% 반영한다. 기업 수 지표에는 영향을 주지 않는다.

지표 계산식

| 지표 | 현재 값 | 계산 | 시뮬레이션 |
|---|---|---|---|
| 24개월 유지율 | 65.8% | 1 − 해지 기업 137 ÷ 400 | 1 − Σ(1 − s') ÷ 400 |
| 월평균 이탈률 | 1.97% | 24개월 해지 수 합 ÷ 24개월 월별 구독 기업 수 합 | 분자는 Σ(1 − s'), 분모는 방어 기업이 더해진 월별 구독 기업 수 합 |
| 연 결제 재계약률 | 87.0% | 1 − 연 결제 해지 34 ÷ 갱신 도래 261 | 분자를 연 결제 해지 기업의 Σ(1 − s')로 바꾼다. 분모 261은 고정 |
| 방어 MRR | 0 | Σ s' × MRR (일시정지 몫은 50%) | 같음 |
| 누적 방어 매출 | 0 | Σ s' × MRR × (해지 월 다음 달부터 2026년 10월까지 개월 수) | 같음 |

갱신 도래 261은 `build_data.py`가 계산한다. 연 결제 기업마다 가입일의 매년 같은 날 중 2024-11-01~2026-10-31에 들고 그 기업의 해지일 + 45일 이전인 날을 센 합이다.

### 5.3 화면

한 화면(스크롤 없음, 1920×1080 기준)에 조작부와 결과를 함께 둔다.

```
┌──────────────┬──────────────────────────────────────────────────────┐
│ 프리셋 4개    │ [유지율] [월 이탈률] [연 결제 재계약률] [방어 MRR] [누적 방어 매출] │
│              │   각 카드: 현재 → 시뮬레이션, 증감                                │
│ A 채용 외 HR │ ┌────────────────────┬───────────────────────────────┐ │
│   레버 1개    │ │ 400개사 점 격자       │ 월별 이탈률 전/후 꺾은선          │ │
│ B 결제·구독  │ │ 유지/해지/방어됨      │                               │ │
│   레버 3개    │ ├──────────┬─────────┴───────┬───────────────────────┤ │
│ C 징후·대응  │ │ 해지 MRR  │ 해지 유형별        │ 해지 요청 흐름 (생키)     │ │
│   레버 3개    │ │ 워터폴    │ 전/후 막대         │ 요청→상담→방어/해지      │ │
│ 재해지율      │ └──────────┴─────────────────┴───────────────────────┘ │
│ [초기화]      │ 가정 기반 시나리오 · 교육용 가상 데이터                         │
└──────────────┴──────────────────────────────────────────────────────┘
```

- **지표 카드 5개**: 24개월 유지율(현재 65.8%), 월평균 이탈률(1.97%), 연 결제 재계약률(87%), 방어 MRR, 24개월 누적 방어 매출.
- **400개사 점 격자**: 기업 1개가 점 1개. 유지는 회색, 해지는 붉은색, 방어됨은 파란색. 방어 기업 수는 기대값을 반올림하고, 방어 확률이 높은 기업부터 파란색으로 바꾼다. 점에 마우스를 올리면 기업의 요금제·결제 방식·해지 유형이 보인다.
- **월별 이탈률**: 현재 선(회색)과 시뮬레이션 선(강조색)을 겹쳐 그린다.
- **해지 MRR 워터폴**: 현재 해지 MRR 9,731만 원에서 묶음 A·B·C의 방어분을 차례로 빼 시뮬레이션 후 해지 MRR에 이른다.
- **해지 유형별 막대**: 6개 유형의 해지 기업 수 전/후.
- **해지 요청 흐름**: 자발 해지 요청이 상담/미상담으로 갈리고 방어/해지로 끝나는 흐름. 전건 상담 레버에 따라 폭이 변한다.
- 각 레버 옆에 대상 기업 수와 참고값의 근거를 작은 글씨로 보여 준다.
- 레버는 슬라이더이며 끌고 있는 동안에도 갱신된다.

### 5.4 배포 (Vercel)

- 사용자가 Vercel 배포를 요청했다. 프로젝트 폴더를 빌드 없는 정적 사이트로 그대로 배포한다 (프레임워크 없음, 빌드 명령 없음, 출력 폴더는 프로젝트 루트).
- 배포에 올리는 것은 `index.html`, `style.css`, `app.js`, `sim.js`, `data.js`, `vendor/`뿐이다. `.vercelignore`로 `tools/`, `docs/`, 원자료 엑셀을 제외한다.
- `data.js`에는 기업명 대신 기업ID만 넣는다. 조원 이름 등 개인 정보는 화면과 배포물에 넣지 않는다.
- 배포 주소는 누구나 열 수 있는 공개 주소다. 내용은 교육용 가상 데이터뿐이다.
- 발표 당일 인터넷이 안 될 때를 대비해 같은 폴더를 `file://`로 여는 방식도 계속 지원한다. 따라서 5장의 "데이터는 스크립트 파일로 내장" 제약은 그대로다.
- 배포 절차: Vercel CLI(`vercel --prod`)로 프로젝트 폴더에서 배포한다. 첫 배포와 그 이후 재배포 모두 사용자 확인 후 실행한다.

## 6. 검증

- `build_data.py`의 정합성 검사 통과, 현재 파일 기준값과 일치 (5.1).
- 원자료 사본에서 해지 확정 1건을 "방어 성공(유지)"로 바꿔 스크립트를 다시 실행했을 때 해지 기업 수가 1 줄고 화면 기준값이 따라 바뀌는지 확인한다. 원본 엑셀은 수정하지 않는다.
- `tools/test_sim.mjs` (Node로 실행):
  - 모든 레버가 "현재"면 결과가 기준값과 같다.
  - 어떤 레버든 값을 올리면 해지 기업 수가 늘지 않는다.
  - 모든 레버가 최대여도 방어 기업 수가 137을 넘지 않는다.
  - 레버별 기여의 합이 전체 방어분과 같다 (기업 수 기준과 매출 기준 모두).
- 배포 후 Vercel 주소에서 화면이 뜨고 `tools/`, `docs/`, 엑셀 파일 경로가 404인지 확인한다.
- 브라우저에서 `index.html`을 `file://`로 열어 네트워크 요청 없이 그려지는지, 각 프리셋과 슬라이더 조작에 모든 차트가 반응하는지, 1920×1080과 1366×768에서 스크롤·잘림이 없는지 화면으로 확인한다.
